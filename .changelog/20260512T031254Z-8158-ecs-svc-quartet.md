- `infra/dev/ecs`: added task definitions, ECS services, NLBs, target groups, listeners, and per-service security groups for the four remaining Python backend services: `summarization`, `notification`, `session-manager`, and `billing`. Each follows the cost-api / admin-api pattern (Fargate ARM64 Graviton, 256 CPU, 512 MiB, port 8000, internal NLB with IP target type, HTTP `/health` probe, ECS deployment circuit breaker with rollback, `lifecycle.ignore_changes = [task_definition, desired_count]` so CD pipelines own the rollout cadence). JWT validation uses the project-standard `JWT_SECRET` / `JWT_ISSUER` / `JWT_AUDIENCE` env contract (NOT the `AUTH_JWT_*` prefix that caused PR #218). Service-specific secrets are resolved at task start by the execution role from the existing IAM allowlist: `ANTHROPIC_API_KEY` for summarization, `SES_SMTP` for notification, `STRIPE_API_KEY` + `STRIPE_WEBHOOK_SECRET` for billing (mapped from the `stripe-test-key` / `stripe-webhook-signing-secret` secrets). Each task SG egresses to the VPC CIDR (interface endpoints), the S3 prefix list (ECR layer downloads), and the DynamoDB prefix list. `nlb_listener_arns` output extended with the four new keys so `infra/dev/api-gateway` discovers them on its next apply. Per-service variables for image tag (default `latest`), container port (8000), CPU / memory, desired_count, log level, health check path, and deregistration delay let production overrides happen without a module rewrite. New per-service outputs cover NLB ARN/DNS, target group ARN, task definition ARN/family, service name/ARN, and task SG ID. README updated with the new services and their env-var contracts.
