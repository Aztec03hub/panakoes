- `infra/dev/*/providers.tf` (21 modules; everything except `network`): added `Service` and `Component` to every module's `default_tags` block so every AWS resource Panakoes creates carries four mandatory cost-allocation dimensions (`Project`, `Environment`, `Service`, `Component`) plus the existing `ManagedBy` + `Module` operator metadata. `Service` is the Panakoes microservice (`auth`, `cost-api`, `admin-api`, `transcription`, `frontend`, `api-gateway`, or `platform` for shared infra); `Component` is the coarse category (`network`, `compute`, `data`, `storage`, `observability`, `security`). Provider-level `default_tags` merges with per-resource `tags` blocks at apply time, so existing `tags = local.common_tags` blocks inherit the new dimensions without per-resource edits. `terraform plan` against each module shows only in-place tag additions (no resource adds or destroys). ADR-043 captures the strategy + alternatives; `docs/runbooks/cost-allocation-tag-activation.md` walks Phil through activating the new tags at the Billing console (one click per tag in Billing > Cost allocation tags > User-defined cost allocation tags), which is the prerequisite for Cost Explorer to treat them as group-by dimensions. The cost-rollup-aggregator Lambda already groups by `SERVICE` (ADR-040), so once the apply lands + the Billing-side activation completes + the ~24-hour backfill finishes, the next nightly aggregator run writes non-`__untagged__` rows to `panakoes-dev-tenant-cost-rollup` and the admin SPA's by-service view becomes non-empty. A per-tenant `TenantId` runtime tag is documented as the future pattern for session-scoped workloads; no Terraform-managed resource sets it.
