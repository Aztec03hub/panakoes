- `infra/dev/ecs/gpu_spawner.tf`: new ECS Fargate task definition + service + internal NLB + target group + listener + task security group for the `gpu-spawner` Python/FastAPI service (ARM64 Graviton, 256/512, port 8000, HTTP `/health` probe). Mirrors the cost-api / admin-api / query-api pattern: inbound from the API Gateway VPC Link SG only; egress to the VPC CIDR (covers the EC2 interface endpoint that `ec2:RunInstances` rides) plus S3 and DynamoDB gateway-endpoint prefix lists. Wires the GPU launch parameters (`GPU_AMI_ID`, `GPU_INSTANCE_TYPE`, `GPU_SECURITY_GROUP_ID`, `GPU_SUBNET_ID`, `GPU_IAM_INSTANCE_PROFILE`, `SESSION_MANAGER_WS_ENDPOINT`, `PROJECT_TAG`, `GPU_SPAWNER_TAG`) as environment variables and pulls `JWT_SECRET` from `panakoes-dev/jwt-signing-secret` via the execution role. `GPU_AMI_ID` is pinned via `var.gpu_spawner_ami_id` to the same bake as `infra/dev/batch/variables.tf` (`ami-0dee04ee5042c94cf`). `GPU_IAM_INSTANCE_PROFILE` consumes the IAM module output `gpu_instance_profile_name` so the spawner's `iam:PassRole` grant stays aligned with the instance profile it actually attaches. `infra/dev/iam/main.tf` moves `gpu-spawner` from `non_ecs_services` to `ecs_services` (provisions a matching ECS execution role with `AmazonECSTaskExecutionRolePolicy` + JWT-secret access), flips the gpu-spawner task role's trust principal from `lambda.amazonaws.com` to `ecs-tasks.amazonaws.com`, and drops the now-unused `AWSLambdaBasicExecutionRole` attachment; the existing `ec2:RunInstances` + `iam:PassRole` policy on the task role is unchanged. `infra/dev/ecs/outputs.tf` appends `"gpu-spawner"` to the `nlb_listener_arns` contract map so the api-gateway module discovers the new NLB on its next apply, and exposes the standard per-service NLB / target group / task definition / service / task SG outputs. `infra/dev/ecs/README.md` documents the env contract and the IAM trust-principal pivot. First deploy references the GHA-baked image tag `initial-<sha>` published by the `image-bake-on-change.yml` workflow (PR #268) once it processes the gpu-spawner Dockerfile; until then the module default is the placeholder `initial` and `TF_VAR_gpu_spawner_image_tag=initial-<sha>` overrides at apply time.
