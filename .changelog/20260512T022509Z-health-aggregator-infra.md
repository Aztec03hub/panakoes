- `infra/dev/ecr`, `infra/dev/observability`, `infra/dev/iam`, `infra/dev/ecs`, `services/admin`: wired the health-aggregator service end-to-end and flipped the admin SPA to live Tier 1 dashboard data. Adds (1) ECR repo `panakoes-dev-health-aggregator` with IMMUTABLE tags, scan-on-push, and the shared 14-day untagged-image lifecycle policy; (2) CloudWatch log group `/panakoes/dev/health-aggregator` (30-day retention, KMS-encrypted with the shared observability CMK, error metric filter inherited from the for_each fan-out); (3) IAM execution role with `secretsmanager:GetSecretValue` scoped to `panakoes-dev/jwt-signing-secret` plus the new log group write grant via the AWS-managed `AmazonECSTaskExecutionRolePolicy`; (4) IAM task role with READ-ONLY scoped grants: `ecs:DescribeServices` / `ecs:ListServices` on the `panakoes-dev` cluster + service ARNs only, `elasticloadbalancing:DescribeTargetHealth` / `DescribeTargetGroups` / `DescribeLoadBalancers` (no resource-level auth on ELBv2 Describe* verbs, so wildcard with action-verb constraint), and `logs:FilterLogEvents` / `DescribeLogGroups` / `DescribeLogStreams` scoped to `/panakoes/dev/*` log-group ARNs (the wildcard stays inside the project namespace); (5) ECS Fargate task definition + service (`infra/dev/ecs/health_aggregator.tf`, ARM64, 256 CPU / 512 MiB, port 8000, JWT_SECRET / JWT_ISSUER / JWT_AUDIENCE + ECS_CLUSTER env, `lifecycle.ignore_changes = [task_definition, desired_count]`, deployment circuit breaker on); (6) internal NLB + IP-target-type target group + TCP listener mirroring `cost_api.tf`; (7) task security group with inbound from the API Gateway VPC Link SG only, NLB healthcheck inbound from VPC CIDR, egress to VPC CIDR (interface endpoints: Secrets Manager, ECR, Logs, STS, KMS, ECS, ELBv2) plus the S3 gateway-endpoint prefix list for ECR image layer downloads (no DynamoDB egress; the aggregator has no DDB tables). The new listener ARN is published in `infra/dev/ecs` output `nlb_listener_arns["health-aggregator"]`; the api-gateway module's `discover_ecs_nlbs=true` mode auto-discovers it on the next apply and provisions `ANY /v1/health-aggregator/{proxy+}` with no explicit override needed (per-route throttling not required for Tier 1). Admin SPA flips: `services/admin/src/lib/config.ts` adds an `envBoolDefaultTrue()` helper and changes the `USE_LIVE_HEALTH_AGGREGATOR` default from false to true; the dashboard's `HEALTH_ENDPOINT` and `serviceDetailEndpoint()` now resolve to `${API_BASE_URL}/v1/health-aggregator/health` and `/v1/health-aggregator/services/<id>` respectively. `services/admin/tests/config.test.ts` and `services/admin/tests/api.test.ts` updated for the flipped default (4 assertions changed; full vitest suite passes: 29/29). README + `.env.example` updated to document the new default and the offline-fallback path via `VITE_USE_LIVE_HEALTH_AGGREGATOR=false`. Dashboard pages that swing to live data on the next SPA redeploy: `/dashboard` (Tier 1 overview, `fetchHealth()` -> live aggregator) and `/dashboard/[service]` (per-service detail drill-down, `fetchServiceDetail(id)` -> live aggregator).
