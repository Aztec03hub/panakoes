- `services/auth-client`: migrated the shared JWT validator library from `python-jose[cryptography]>=3.3` to `PyJWT[crypto]>=2.10.1`. The dependency change removes the transitive `python-ecdsa` library (carrier of the unpatched Minerva CVE GHSA-wj6h-64fc-37mp); PyJWT calls the `cryptography` package directly with no python-ecdsa shim. `JwtValidator` and `JwksJwtValidator` keep their public API byte-identical (same constructors, same `validate()` signatures, same `from_jwks_url` factory, same `JwtInvalidError` failure mode); only the underlying chained exception types change (`jwt.InvalidTokenError` and `jwt.ExpiredSignatureError` replace `jose.JWTError` and `jose.ExpiredSignatureError`, never echoed to clients). JWKS-backed RS256 validation now wraps each cached JWK dict in `jwt.PyJWK.from_dict(..., algorithm="RS256")` before passing the resolved key to `jwt.decode`; the public RSA key is the same cryptographic material, so the round-trip + tamper-rejection semantics are unchanged. Test fixtures switched from `jose.jwk.construct` + `bytes -> str` normalisation to `jwt.algorithms.RSAAlgorithm.to_jwk` (which already returns str-encoded `n`/`e`/`kty`). One new test (`test_jwks_validator_rejects_malformed_jwk_in_cache`) exercises the PyJWK parse-error path, taking validator.py to 100% coverage. PR B of 9 in the python-jose ecosystem CVE remediation series.
