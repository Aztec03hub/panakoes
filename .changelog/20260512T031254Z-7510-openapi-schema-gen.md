- `services/cost-api` + `services/admin-api`: emit and check in OpenAPI 3.1 schemas so the admin SPA's future TypeScript client codegen and external integrators read from a stable artifact rather than a live API. Each service ships a `scripts/emit-openapi.py` that imports its FastAPI app, calls `app.openapi()`, strips the environment-specific `servers` array, and writes `openapi.json` next to the service's `pyproject.toml` pretty-printed with sorted keys (so git diffs are review-friendly). The checked-in `services/cost-api/openapi.json` covers `/health` plus the four cost routes (`/api/v1/cost/by-service`, `/by-tenant`, `/forecast`, `/anomalies`); `services/admin-api/openapi.json` covers `/health` plus the nine lifecycle ops and `/audit-log`. Both services now gate Swagger UI (`/docs`), ReDoc (`/redoc`), and the live `/openapi.json` endpoint on a new `ENABLE_OPENAPI_DOCS` env var (default true so contributors can poke at the schema in dev; production deploys flip it off so the interactive docs surface never reaches the public internet). New repo-root Makefile targets `openapi-emit` and `openapi-check` regenerate the artifacts and gate on drift. New `.github/workflows/openapi-schema-drift.yml` re-emits in CI and fails the PR with an actionable hint if the checked-in schema is stale. New per-service integration tests (`tests/integration/test_openapi_schema.py`) assert the live `/openapi.json` advertises every route the SPA depends on plus a Swagger UI smoke test. `CONTRIBUTING.md` documents the workflow; `services/admin/README.md` documents the codegen one-liner (`openapi-typescript services/cost-api/openapi.json --output src/lib/generated/cost-api.d.ts`) which lands in a follow-up PR alongside the first generated client.
