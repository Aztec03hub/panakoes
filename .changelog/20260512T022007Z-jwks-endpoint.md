- `services/auth`, `services/auth-client`, `infra/dev/auth-kms-signing`: RS256 JWT signing path via AWS KMS plus a live JWKS endpoint at `/.well-known/jwks.json` (ADR-041 phase 1). The auth service gains two env vars: `AUTH_JWT_ALGORITHM` (HS256 default; RS256 opt-in) and `AUTH_JWT_KMS_KEY_ID` (required when RS256, ignored otherwise). When RS256 is selected, the service signs JWTs via `kms:Sign` against an `RSA_2048` asymmetric KMS key (private key material never leaves KMS) and the JWKS endpoint surfaces the public key (fetched via `kms:GetPublicKey`, cached 10 minutes). JWT headers carry a `kid` matching the KMS key's UUID so verifiers can match the JWKS entry without trial-decryption. New `services/auth/src/auth/kms-signer.ts` wraps the KMS client behind an injectable `KmsSigner` interface; `signJwt` / `signStepUpToken` / `verifyJwt` / `verifyStepUpToken` accept an optional signer arg so the HS256 path is byte-identical when no signer is wired. Python validator gains `JwtValidator.from_jwks_url(url, issuer, audience)` plus `from_env()` JWKS-mode auto-detect (triggered by `JWT_PUBLIC_JWKS_URL`); `JwksJwtValidator` subclasses `JwtValidator` and locks the algorithm to RS256 in JWKS mode (HS256 cannot be JWKS-validated). New Terraform module `infra/dev/auth-kms-signing/` provisions a single `aws_kms_key` (customer_master_key_spec `RSA_2048`, key_usage `SIGN_VERIFY`, alias `alias/panakoes-dev-jwt-signing`, 30-day deletion window) with a root-only key policy; `infra/dev/iam` grants the auth task role `kms:Sign + kms:GetPublicKey + kms:DescribeKey` scoped to the single key ARN; `infra/dev/ecs` adds `auth_jwt_algorithm` and `auth_jwt_kms_key_id` variables (defaults preserve the HS256 baseline). ADR-041 documents the migration timeline (phase 1 ships the path; phase 2 flips production after a separate PR; phase 3 deprecates HS256 after one week of RS256 stability). 31 new unit tests in the auth service and 16 new in the Python validator; HS256 regression-free with all 41 pre-existing auth-service unit tests passing and all 50 pre-existing Python validator tests passing; coverage is 100% on every new and changed source file under the auth-path 100% gate (ADR-018). `services/auth/README.md` and `services/auth-client/README.md` document the new env vars and constructor. Phase 1 is fully opt-in: setting `AUTH_JWT_ALGORITHM=RS256` is the only switch; no production behaviour changes without that flip.
