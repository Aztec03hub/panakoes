- `services/billing` + `services/auth` + `services/middleware-lib` + `infra/dev/data` + `infra/dev/iam`: wired the real Stripe webhook handler and plan-gating JWT claim. The billing service now handles the five canonical Stripe webhook events (`checkout.session.completed`, `customer.subscription.created`, `customer.subscription.updated`, `customer.subscription.deleted`, `invoice.payment_failed`; `invoice.paid` is also recognised for the payment-success audit trail) with cryptographic Stripe-Signature verification (rejecting on missing / blank / invalid signatures with HTTP 400 and a `billing.webhook_signature_invalid` audit event). Subscription-state events project onto a new `panakoes-dev-subscriptions` DynamoDB table (pk=`tenant_id`, sk=`subscription_id`, attributes `plan` / `status` / `current_period_end` / `cancel_at` / `quantity` / `stripe_customer_id` / `last_event_id` / `updated_at`), provisioned in `infra/dev/data/main.tf` with PITR + deletion protection and reachable from the billing task role via the updated `infra/dev/iam` policy. Idempotency is enforced by a conditional `PutItem` keyed on `last_event_id`: a Stripe replay of the same `evt_...` id returns 200 `{"status": "duplicate"}` and writes nothing to either the subscriptions table or the event log. The new `SubscriptionStore.get_plan(tenant_id)` returns the highest-privilege active plan (team > pro > free; canceled / unpaid rows excluded; past_due retained per Stripe convention). The TypeScript auth service's JWT contract now carries a `plan: "free" | "pro" | "team"` claim (defaults to `free` when sign-in cannot resolve a paid tier), surfaced as `JwtClaims.plan?` on the input shape and `VerifiedJwt.plan` (required, default `free`) on the verified shape; tampered or unknown claim values are coerced to `free` rather than silently upgraded. The new `panakoes_middleware.require_plan("pro" | "team")` FastAPI dependency reads `request.state.user.plan` (attribute or mapping form) and raises HTTP 402 Payment Required with `{"detail": "plan_required", "required_plan": ..., "current_plan": ...}` when the claim is below the threshold; missing authentication raises 401 instead of 402 because authentication is the precondition for plan-gating. Coverage: new `tests/unit/test_subscription_store.py` (9 tests covering insert, idempotent-replay, overwrite-on-new-event-id, free-for-unknown-tenant, canceled-drops-to-free, multi-subscription-picks-highest, past-due-retains-access, table_name property, cancel_at ISO 8601 serialisation), new `tests/integration/test_webhook.py` cases for `customer.subscription.created`, the idempotency contract, the deleted-flips-to-free path, and the subscription-event-without-subscription-id graceful skip, new `services/middleware-lib/tests/unit/test_plan_gating.py` (parameterised matrix of admit / 402 cases plus 401-no-principal, dict-principal, unknown-plan-coerces-to-free, and the internal `_coerce_plan` helper), and new `services/auth/tests/unit/jwt-plan.test.ts` (default-free / explicit-pro / explicit-team / unknown-falls-back-to-free). `services/billing/README.md` documents the webhook URL Phil registers in the Stripe Dashboard, the five events to subscribe to, the subscription-state table schema, the idempotency contract, and the full 402 plan-gating matrix.
