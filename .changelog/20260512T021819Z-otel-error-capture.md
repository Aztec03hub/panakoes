- `services/otel-lib`, `services/otel-lib-ts`: capture uncaught exceptions, errored spans, and Python `logging.ERROR`+ records as OTEL exception events that flow to the OTLP exporter. Python `configure()` auto-installs `sys.excepthook`, `threading.excepthook`, the asyncio loop's `default_exception_handler`, and a logging filter on the root logger (mirrored across descendants via a `Logger.handle` patch so it covers every handler regardless of the host's logger topology). TypeScript `configure()` auto-installs `window.onerror`, `window.onunhandledrejection`, `process.on("uncaughtException")`, and `process.on("unhandledRejection")`. Each handler records the exception on the active span or starts a one-shot `uncaught_exception` span when none is active, and force-flushes the exporter on fatal Node-side paths. Opt-out via `OTEL_DISABLE_ERROR_CAPTURE=true` for tests that intentionally throw. Both lib READMEs and `CHANGELOG.md` updated; 13 new Python tests and 13 new TypeScript tests cover the install/uninstall lifecycle, the four hooks individually, the opt-out flag, and the no-active-span fallback path. Default is capture-on because errors going untracked is strictly worse than test noise.
