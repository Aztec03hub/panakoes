- `services/ingestion-api` + `services/session-manager`: standardized the JWT validator env-var prefix to `JWT_*` (was `AUTH_JWT_*`) across both services' `pydantic-settings` config classes, FastAPI auth dependencies, pytest `conftest.py` env wiring, and READMEs. This makes every Python validator in the repo consume the same `JWT_SECRET` / `JWT_ISSUER` / `JWT_AUDIENCE` env contract that `panakoes_auth_client.from_env()` reads (the canonical source in `services/auth-client/src/panakoes_auth_client/config.py`), matching the convention `cost-api` and `admin-api` adopted in PR #218. The signer side (`services/auth`, the Better-Auth TypeScript service) keeps `AUTH_JWT_*` on purpose because Better-Auth library conventions use that naming and the verbal distinction makes operator mistakes (wiring a signer's secret into a validator's env or vice versa) catch at boot time. New `CONTRIBUTING.md` "Conventions / JWT env-var naming" section codifies the signers-vs-validators rule and gives a 3-step checklist for new Python validator services. New per-service unit tests `tests/unit/test_config_env.py` pin the contract: a positive test asserts `JWT_SECRET` resolves to `settings.jwt_secret`, and a regression test asserts the legacy `AUTH_JWT_SECRET` env var does NOT bleed into the validator's field. No Terraform changes were needed because neither service has ECS wiring landed yet; when their `infra/dev/ecs/<svc>.tf` lands it must mirror the `cost_api.tf` / `admin_api.tf` shape (`JWT_SECRET` as ECS secret, `JWT_ISSUER` / `JWT_AUDIENCE` as plain env tracking `var.auth_jwt_issuer` / `var.auth_jwt_audience`).
