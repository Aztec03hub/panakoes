- `docs/runbooks/async-transcription-smoke.md`: new operator runbook for the async transcription path. Two lanes: Lane A drives the `panakoes-dev-transcribe-worker` Lambda (Groq backend) via the EventBridge -> SQS -> Lambda chain wired by `infra/dev/transcribe-worker/`, and Lane B submits a single GPU Whisper job against `panakoes-dev-transcribe-queue` (job definition `panakoes-dev-transcribe-batch:1`, g4dn.xlarge Spot). Includes a current path-status table verified against the dev account on 2026-05-11 (Lambda DEPLOYED, Batch compute env ENABLED + VALID + Healthy, queue ENABLED, job def ACTIVE, but the `panakoes-dev-transcriber-batch:latest` ECR image is NOT PUSHED and the `services/transcriber-batch/` source directory does not exist in the monorepo). Documents the `PendingVerification` fall-through on first GPU Spot launch per memory, the cleanup commands for both lanes, the verification criteria (DLQ depth 0, transcript artifact landed, alarm OK, desired_vcpus returned to 0), and a "Pending: roll Batch CE to bespoke GPU AMI" section explaining why a naive `terraform apply` on `infra/dev/batch/` fails (compute environment replacement blocked by JobQueue relationship) and the queue-disable + detach + apply + re-enable recovery sequence (or the `name_prefix` + `create_before_destroy` refactor that makes future rolls zero-downtime). The Batch compute environment currently runs the stock AL2023 NVIDIA AMI `ami-091f07e77f51e6b42` rather than the bespoke `ami-0dee04ee5042c94cf` from PR #237; rolling that change is the documented follow-up and was deferred in this PR because the smoke target (Lane B) is independently blocked on the missing GPU container image.
