category: Changed

- `services/auth` + `infra/dev/iam`: the auth service now reads each user's current plan from the `panakoes-dev-subscriptions` DynamoDB table at sign-in / sign-up time and bakes the tier into the JWT's `plan` claim, closing the plan-gating loop with `middleware-lib`'s `require_plan(...)` (which previously always saw `"free"` because the auth service hard-coded the claim). New `services/auth/src/billing/subscription-lookup.ts` exposes `createPlanLookup({ddb, tableName, logger}).getActivePlan(userId)`: queries with `pk = tenant_id` (v0.1 assumption: `tenant_id = user.id`; multi-tenant resolution is tracked as a follow-up ADR), only rows in `{"active", "trialing"}` count as entitling, returns the highest tier across active rows (`team` > `pro` > `free`), caches lookups in-memory with a 60-second TTL keyed by `tenant_id` (Stripe webhooks intentionally do NOT push cross-service invalidation; 60s staleness is the dev trade-off, ElastiCache + webhook invalidation is a v0.3 follow-up), and fail-closes to `"free"` on any DDB error (network, throttle, `ResourceNotFoundException`, `AccessDeniedException`) so a flaky DDB never elevates the plan claim. `signJwt` and `verifyJwt` in `src/auth/jwt.ts` now carry the `plan` claim end-to-end; the input shape keeps `plan` optional (defaults to `"free"` at sign time so legacy / test callers stay deterministic), and verify degrades unknown or missing plan values to `"free"` so older tokens issued before this slice continue to verify through the rollout window. `src/server.ts` constructs a real `DynamoDBClient` pointed at `config.AWS_REGION` and `config.DDB_SUBSCRIPTIONS_TABLE` (both new optional env-vars defaulting to `us-east-1` and `panakoes-dev-subscriptions`); integration tests inject a stub `PlanLookup` via the new `stubPlanLookup(plan)` helper in `tests/helpers.ts` so they need neither AWS credentials nor a real table. New unit tests in `services/auth/tests/unit/subscription-lookup.test.ts` cover the four brief-required paths (pro / team / free-no-row / free-canceled) plus tier-precedence on multiple active subs, the 60s cache TTL behaviour, fail-closed posture on DDB throws (Error and non-Error), unknown plan strings and unknown statuses, partial-write defensiveness, the DDB query shape (`KeyConditionExpression = "pk = :pk"`), and the default-clock branch when `now` is omitted. New integration tests in `services/auth/tests/integration/plan-claim.test.ts` confirm the plan claim threads through sign-up and sign-in to the verified JWT for each of `free` / `pro` / `team` and for the canceled-subscription path. `services/auth/README.md` documents the lookup contract, the v0.1 tenant-id-is-user-id assumption, the cache TTL, and the multi-tenant follow-up. `infra/dev/iam/main.tf` grants the auth task role `dynamodb:Query` + `dynamodb:GetItem` on the forward-referenced `panakoes-dev-subscriptions` table (+ `index/*`); billing remains the sole writer. The hot path (every JWT verification) is unchanged: `verifyJwt` reads `plan` from the token, never from DDB; only the signer (one call per sign-in) touches DDB. Rebase dependency: PR #247 (Stripe webhooks + subscriptions table) has not yet merged at the time of this slice. Until #247 lands and the data module provisions the `panakoes-dev-subscriptions` table, the auth lookup hits `ResourceNotFoundException` and fail-closes to `"free"` for every user (same behaviour as before this slice, no user-visible regression). When #247 lands, the table comes into existence and the plan claim starts reflecting real subscription state on the next sign-in per user.
