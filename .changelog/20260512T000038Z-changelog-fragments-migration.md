- `.changelog/` + `scripts/assemble-changelog.sh`: migrated the project from a monolithic `CHANGELOG.md` append-on-every-PR pattern to per-PR Markdown fragment files. Each PR now drops one `.changelog/<UTC-timestamp>-<short-slug>.md` fragment with YAML frontmatter (`category: Added|Changed|Deprecated|Removed|Fixed|Security`) and a terse user-visible bullet body; at release time, `scripts/assemble-changelog.sh --version vX.Y.Z --prune` collects all fragments, groups by Keep a Changelog category in canonical order (Added, Changed, Deprecated, Removed, Fixed, Security), prepends a new versioned block to `CHANGELOG.md`, and deletes the fragments. The `--dry-run` flag previews without writing. `.github/workflows/changelog-check.yml` was updated to accept either a `.changelog/*.md` change OR a direct `CHANGELOG.md` change in the PR diff. The prior `CHANGELOG.md merge=union` line in `.gitattributes` is kept as a belt-and-suspenders fallback. Rationale: per-file fragments eliminate the shared-write contention that marked all sibling PRs `DIRTY` on every merge (the dominant PR-backlog churn source observed during the 2026-05-08 drain); auto-merge no longer stalls waiting for manual rebases. `CLAUDE.md`, `CONTRIBUTING.md`, and the sub-agent brief templates were updated to reference the new pattern. Tests live at `tests/scripts/test_assemble_changelog.sh`.
