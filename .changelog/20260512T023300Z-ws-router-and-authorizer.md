- `services/ws-authorizer/`: new Python Lambda (container image) serving as the API Gateway v2 REQUEST-type authorizer on the `$connect` route of `panakoes-dev-streaming-ws`. Validates a panakoes-issued HS256 JWT via the shared `panakoes-auth-client` library; accepts the token in either `Authorization: Bearer <jwt>` (header) or `?token=<jwt>` (query string, the browser-mic path) with header winning on conflict. Returns `{isAuthorized: true, context: {user_id, tenant_id, role}}` on success or `{isAuthorized: false}` on every failure mode (missing-token, malformed header, bad signature, expired, wrong issuer/audience, malformed JWT, missing required claim, config-error). 100% branch coverage on the auth path (21 unit tests). Container image built from `services/ws-authorizer/Dockerfile` at repo-root context to pull in the sibling `services/auth-client/` path-dep.
- `services/streaming-router/`: new Python Lambda (container image) that replaces the smoke-deploy stub on every route of `panakoes-dev-streaming-ws`. Branches on `requestContext.routeKey`: `$connect` writes a session row to `panakoes-dev-streaming-sessions` (status=connecting, captures `user_id`/`tenant_id`/`role` from the authorizer context) and fires a `streaming.session.connecting` event to EventBridge for gpu-spawner; `$disconnect` flips the row to status=disconnected with a timestamp via a conditional UpdateItem so a ghost-session disconnect is idempotent; `audio-frame` forwards the body to the `panakoes-dev-streaming-ws-frames` SQS queue with a `session_id` MessageAttribute (forward-compat for FIFO); `transcript-request` returns the row's `last_transcript` field (stub for the GPU worker to populate); `$default` and any unknown action log at WARN and return 200 for forward-compat. 94% branch coverage (10 moto-backed unit tests covering every route + idempotency edge cases).
- `infra/dev/api-gateway-ws/main.tf`: replaced the inline stub Lambda with a wire-up of the real streaming-router + ws-authorizer Lambdas. New resources: `aws_apigatewayv2_authorizer.jwt` (REQUEST-type, no cache, identity sources `route.request.header.Authorization` + `route.request.querystring.token`), `aws_lambda_function.streaming_router` and `aws_lambda_function.ws_authorizer` (both container-image, image URIs sourced from `infra/dev/ecr/` via remote state), per-Lambda CloudWatch log groups under `/aws/lambda/panakoes-dev-streaming-*` with a shared module-local CMK (the observability shared CMK conditions encryption on `/panakoes/dev/*` so a dedicated CMK is required for Lambda log groups; same pattern as transcribe-worker and cost-rollup-aggregator), inline IAM policies scoped tightly to the streaming-sessions table ARN + the audio-frame SQS queue ARN + `execute-api:ManageConnections` on this API's connection ARNs + `events:PutEvents` on the streaming event bus for the router, and `secretsmanager:GetSecretValue` on the single `panakoes-dev/jwt-signing-secret` ARN plus `kms:Decrypt` conditioned on `kms:ViaService = secretsmanager.us-east-1.amazonaws.com` for the authorizer. `aws_apigatewayv2_route.connect` now uses `authorization_type = CUSTOM` with `authorizer_id` pointing at the new authorizer. `aws_apigatewayv2_integration.stub` keeps its resource name (state continuity from PR #281) but its `integration_uri` flips from the inline stub to `aws_lambda_function.streaming_router.invoke_arn`, so the apply is an in-place update plus a route attribute change rather than a cascade-replace. New variables `streaming_router_image_tag`, `ws_authorizer_image_tag`, `jwt_issuer`, `jwt_audience`, `streaming_event_bus`.
- `infra/dev/ecr/main.tf`: added `streaming-router` and `ws-authorizer` to the services list so two new ECR repositories (`panakoes-dev-streaming-router`, `panakoes-dev-ws-authorizer`) provision under the existing shared CMK + lifecycle policy.
- `infra/dev/api-gateway-ws/`: new Terraform module that provisions the dev streaming WebSocket API (`panakoes-dev-streaming-ws`, id `a75u8kj039`, `wss://a75u8kj039.execute-api.us-east-1.amazonaws.com/dev`). Separate from `infra/dev/api-gateway/` because a single `aws_apigatewayv2_api` cannot serve both `HTTP` and `WEBSOCKET` protocol types and because splitting state isolates blast radius across the two transport lanes. Routes registered: `$connect`, `$disconnect`, `$default`, `audio-frame`, `transcript-request`; route selection on `$request.body.action`. Stage `dev` with `auto_deploy = true`, default per-route throttling (500 burst / 200 rate), structured-JSON access logging to `/aws/apigatewayv2/panakoes-dev-streaming-ws` (30-day retention, module-local KMS CMK), execution logging at INFO level with `data_trace_enabled = false` so audio payloads never land in CloudWatch. The module also stands up the account-level API Gateway CloudWatch Logs role (account-wide singleton previously unset, hit on first `CreateStage` with `BadRequestException: CloudWatch Logs role ARN must be set`). Smoke-deploy integration target is a 35-line inline Python Lambda (`panakoes-dev-streaming-ws-stub`) that logs every event and forwards to an SQS queue (`panakoes-dev-streaming-ws-frames`, 60s visibility, 4h retention, SQS-managed SSE); the follow-up PR repoints the integration URI from the stub to the real streaming-router Lambda when it lands. Lambda authorizer planned for `$connect` (HS256 JWT via the `panakoes-auth-client` layer, claim shape locked in `services/auth-client/src/panakoes_auth_client/claims.py`) is intentionally deferred to a follow-up PR; `$connect` currently runs with `authorization_type = "NONE"`. End-to-end smoke against the deployed API confirmed all five routes dispatch cleanly (CONNECT → audio-frame → transcript-request → $default → DISCONNECT, status 200 each, integrationLatency under 300ms cold / 60ms warm) with no dangling connections.
- `docs/runbooks/streaming-websocket-smoke.md`: new operational runbook for the streaming WebSocket API. Documents the prerequisites (`websocat`, `panakoes-admin` profile, `jq`), the five-step smoke procedure (purge queue, confirm empty, connect with three test frames, poll queue for the five expected route dispatches, inspect access + Lambda logs), the verification criteria, the Lambda authorizer JWT shape the follow-up PR will validate (HS256, iss `https://auth.panakoes.com`, aud `panakoes-api`, with the full `JwtClaims` field list and the `?access_token=<jwt>` query-string identity-source pattern), rollback posture (revert the bad commit and re-apply, not `terraform destroy`), and three concrete troubleshooting cases (stale deployment, missing Lambda permission, route pointing at a stale integration after a Terraform replace). Added to `docs/runbooks/README.md` index.
