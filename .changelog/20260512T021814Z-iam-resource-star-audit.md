- `infra/dev/{api-gateway,cost-rollup-aggregator,frontend,observability,security,step-functions,transcribe-worker,waf}`: audited the 19 `IAM Resource = ["*"]` usages flagged by the custom CodeQL query `panakoes-iam-policy-resource-star` (introduced in PR #280). Every hit is annotated with an inline `# panakoes-iam-policy-resource-star: justified` comment that names the AWS-side constraint forcing the wildcard and links the AWS documentation. 15 of the 19 sit inside `aws_kms_key.policy` documents where `Resource: *` resolves to the single owning key by design (the key ARN does not exist at policy-document evaluation time and AWS resolves `*` against the attached key only). The remaining 4 cover AWS APIs without resource-level authorization per the service-authorization reference: Cost Explorer (`ce:GetCostAndUsage`, `ce:GetDimensionValues`) in `cost-rollup-aggregator`; AWS Batch (`batch:DescribeJobs`) in `step-functions`; and the CloudWatch Logs `*LogDelivery` / `PutResourcePolicy` / `DescribeLogGroups` family required by Step Functions Standard logging in `step-functions`. Audit was annotation-only: 0 tightened (no candidate hit supports resource-level auth), 19 justified. `terraform fmt` and `terraform validate` clean across all 8 modules; `terraform plan` shows policy-document text-only diffs with no resource adds/destroys/replacements. The justified-comment marker lets the CodeQL query suppress these false-positives going forward without weakening the rule for new code paths.
