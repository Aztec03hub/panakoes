- `infra/global/cloudflare-dns/`: new Terraform module that brings the DNS records on both LaFayette Labs Cloudflare zones (`panakoes.com` and `lafayettelabs.com`) under version control. Uses the `cloudflare/cloudflare ~> 4.0` provider and reads its API token from `var.cloudflare_api_token` (populated via the operator-local `TF_VAR_cloudflare_api_token` env var; never committed). Manages 24 DNS records total: 12 on `panakoes.com` (`_amazonses` TXT, 3 SES DKIM CNAMEs, apex + www CNAMEs to the future Cloudflare Pages landing site from PR #275, `_dmarc` TXT with `p=quarantine; rua=mailto:security@lafayettelabs.com`, apex SPF TXT authorizing Cloudflare Email Routing + Amazon SES, and 3 Cloudflare Email Routing MX records that back the `security@`/`conduct@`/`noreply@` aliases) and 12 on `lafayettelabs.com` (existing apex + www CNAMEs to the live Cloudflare Pages site, `_amazonses` TXT, 3 SES DKIM CNAMEs from PR #265, matching `_dmarc` + SPF + Email Routing MX records). Every existing manually-added record is brought into state via `terraform import` rather than re-created; `infra/global/cloudflare-dns/README.md` documents the exact import command list, the API-token scope spec (`Zone:Read` + `Zone Settings:Edit` + `DNS:Edit` restricted to the two specific zones via Cloudflare's "Zone Resources > Include > Specific zone" picker), the variable-population workflow (zone IDs from the dashboard, SES tokens via `aws ses get-identity-dkim-attributes` + `aws ses get-identity-verification-attributes`), the `dig`-based verification queries, and a rollback procedure that explicitly forbids `terraform destroy` (would black-hole every domain). State key `global/cloudflare-dns/terraform.tfstate` lives in the bootstrap S3 backend alongside every other Panakoes module; `infra/README.md` index updated. API Gateway custom-domain CNAMEs from PR #264 and the `admin.panakoes.com` CloudFront CNAME are flagged as follow-up work to add + import once those upstream PRs land. This PR is module-authoring only; Phil runs the first `terraform init` + import + plan + apply post-merge from his local machine with the API token exported via `TF_VAR_cloudflare_api_token`.
