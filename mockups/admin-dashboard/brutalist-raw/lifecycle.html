lifecycle controls

Tier 3 of the admin dashboard. Every dangerous operation routes through the typed-confirmation, idempotency-by-key, step-up MFA, and audit-before-AND-after safety pattern (ADR-032). Read the runbook before you touch anything here.

[WARN]   admin-api revalidates the confirmation string and idempotency key server-side regardless of what the UI does. A fresh idempotency key is minted on every submit (replays collapse to one effect per ADR-032 layer 2).

1. choose operation

terminate-session :: ends a live streaming session, releases the GPU back to the pool. params: session_id, reason.

2. target

id>

stable identifier. format depends on op (sess_*, ing_*, user_*).

free-form. logged verbatim into the audit row's payload.

3. typed confirmation

enter the target id above to reveal the confirmation string.

!>

[WARN] does not match the expected confirmation string.

4. submit

step-up MFA: [OK]   idempotency-key: minted on submit
