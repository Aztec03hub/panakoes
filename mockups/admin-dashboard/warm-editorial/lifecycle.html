The safety pattern, in four layers.

ADR-032 · defence in depth

The Tier 3 lifecycle endpoints share a single safety pattern with four independently-failing layers. Each layer is cheap to add, and the combination is what makes the operator confident at 2am.

Layer one: typed confirmation. The operator must type the exact string above by hand. Copy-paste works but defeats the purpose, so the field is monospace and fixed-width to make the keystrokes deliberate.

Layer two: idempotency key. The client mints a fresh UUIDv7 on every submit. Duplicates collapse server-side to a single effect, which turns "did my retry double-up" into a non-question.

Layer three: step-up MFA. Better-Auth requires a second factor within the last fifteen minutes, regardless of session age. The countdown is visible at the top of every Tier 3 page.

Layer four: audit before and after. The intent row is written before the operation starts. The result row is written after. A partial failure is forensically reconstructible from the pair, even if the result row never lands.
