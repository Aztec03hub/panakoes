Read the runbook before you touch anything here.

Tier 3 of the admin surface. Every dangerous operation routes through the same envelope: a typed-confirmation string the operator has to reproduce verbatim, an idempotency key the page mints on every submit so deliberate retries are distinct from stuck-client replays, and an audit row written both before and after the operation so partial failures stay forensically reconstructible. Why a 200 with status=failed. ADR-033 separates HTTP transport failures (4xx, 5xx, network) from protocol failures (the operation reached admin-api and was rejected by business logic). The latter come back 200 with status: "failed" so a stuck client cannot replay-bomb a known-bad request expecting different results. The audit row is written either way.
