### Added
- Wired the `panakoes-otel` shared instrumentation library into every existing Python service. FastAPI services (`services/_template/`, `services/ingestion-api/`, `services/notification/`, `services/query-api/`) call `panakoes_otel.configure()` from a `lifespan` context manager, then run `instrument_fastapi(app)` + `instrument_boto3()` (+ `instrument_httpx()` for `notification`, the only service with outbound httpx traffic), and call `shutdown()` on lifespan exit to flush exporters. The Lambda service (`services/event-router/`) configures OTel and `instrument_boto3()` at module import time as its cold-start hook, guarded by a module-level Once-flag so warm-container re-imports never reconfigure; `shutdown()` is intentionally not called because the Lambda runtime tears the container down on its own schedule. The `services/_template/main.py` skeleton carries the canonical wiring so every new service inherits it via copy. Each service's `pyproject.toml` adds `panakoes-otel` to `dependencies` plus a `[tool.uv.sources]` path-dep entry mirroring the `panakoes-audit` pattern, and a `[[tool.mypy.overrides]]` block ignoring `panakoes_otel.*` missing-import noise. Each service's README "Environment variables" section documents `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_SDK_DISABLED`, `SERVICE_VERSION`, and `DEPLOYMENT_ENVIRONMENT`. Per-service test conftests pin `OTEL_SDK_DISABLED=true` so the lifespan installs NoOp providers and no exporter sockets open during the suite. Event-router's Dockerfile and `requirements.txt` gain the otel-lib path-dep alongside the existing audit-lib path-dep so the deployment package picks it up.

- `panakoes-models` library at `services/models-lib/`. Shared Pydantic v2 models that every Panakoes Python service imports for typed cross-service contracts. Eight modules cover the canonical shape of every domain object: `users` (User, UserId), `ingestion` (IngestionRecord, IngestionStatus with the full `pending -> uploaded -> transcribing -> transcribed -> summarizing -> summarized -> failed` lifecycle, 10 GiB upload cap), `transcripts` (Transcript, TranscriptSegment with start/end ordering validation), `summaries` (Summary, SummaryTier `haiku`/`sonnet`), `sessions` (StreamingSession, SessionStatus), `notifications` (NotificationRecord with ULID-shape Crockford-base32 ids, NotificationKind, NotificationStatus), `billing` (Subscription, BillingTier; slice-1 skeleton), `errors` (ApiError envelope). Every model is `frozen=True`, `extra="forbid"`, strips whitespace on string fields, and rejects naive or non-UTC datetimes at construction. Identifier newtypes use Pydantic `StringConstraints` regex validation (UserId, IngestionId, TranscriptId, SummaryId, SessionId, NotificationId). 100% test coverage across 158 unit tests covering construction, every regex/constraint failure, enum exhaustiveness, JSON round-trip, frozen-instance enforcement, and `extra='forbid'`. Ships a PEP 561 `py.typed` marker so consumers get full type-checker support.

- `panakoes-otel` library at `services/otel-lib/`. Shared OpenTelemetry instrumentation that every Python microservice imports to wire traces, metrics, and logs through one consistent OTLP/gRPC pipeline. Public API: `configure(service_name, environment="dev", endpoint=None)` installs SDK TracerProvider/MeterProvider/LoggerProvider with W3C TraceContext + Baggage propagation and resource attributes (`service.name`, `service.namespace="panakoes"`, `service.version` from `SERVICE_VERSION` env, `deployment.environment`); `instrument_fastapi(app)`, `instrument_boto3()`, `instrument_httpx()` enable per-library auto-instrumentation; `get_tracer(name)` / `get_meter(name)` are convenience getters; `shutdown()` flushes and tears down providers. Endpoint resolves explicit-arg > `OTEL_EXPORTER_OTLP_ENDPOINT` > `http://localhost:4317`. Setting `OTEL_SDK_DISABLED=true` wires NoOp providers for tests + offline dev. - Event Router Lambda v0.1 at `services/event-router/`. Python 3.12 container-image Lambda that processes S3 `ObjectCreated:*` events on the audio-uploads bucket. Parses the object key `audio/{user_id}/{ingestion_id}/{filename}`, conditionally flips the matching `panakoes-dev-ingestion` DDB record from `pending` to `uploaded` (idempotent via `ConditionalUpdate`), and publishes a `panakoes.ingest / AudioUploaded` EventBridge event so the transcription pipeline can pick the upload up. Supports both raw S3-event and EventBridge-wrapped trigger shapes. Unmatched routes (unparseable key or absent DDB row) are logged and emit a `panakoes/dev/event-router::unknown_record` CloudWatch metric with a `Reason` dimension; correctness path is robust to metric publication failure. Env vars: `DDB_INGESTION_TABLE`, `EVENTBRIDGE_BUS_NAME`, `AWS_REGION`. 25 unit tests at 97% coverage (90% gate enforced); ruff and mypy strict clean. Multi-stage `public.ecr.aws/lambda/python:3.12` Dockerfile (build context = repo root) bundles the `panakoes-audit` path-dep alongside the handler. `requirements.txt` provided alongside `pyproject.toml` so reviewers and the deploy pipeline can read the runtime surface without resolving the lock file.
- Packer scaffold at `infra/ami/gpu-transcribe/` that bakes the custom GPU AMI used by both Panakoes transcription paths (async Batch and session-spawned streaming). Source AMI resolved at build time via the `amazon-ami` data source with `most_recent = true`, owner-filtered to AWS's Deep Learning AMI publisher and name-pattern-filtered to the Ubuntu 22.04 GPU base. Build host is g4dn.xlarge so the CUDA tooling check exercises the same hardware family used at runtime. Three shell provisioners run in order: `scripts/install-models.sh` downloads and SHA256-verifies (via `openssl dgst`) the Whisper-large-v3 fp16 weights to `/opt/whisper/models/large-v3.pt`, the faster-whisper-large CT2 weights tarball to `/opt/whisper/models/faster-whisper-large/`, and the Silero VAD weights to `/opt/whisper/models/silero-vad.jit`; `scripts/install-runtime.sh` authenticates Docker against the per-environment ECR registry and pulls the transcriber-stream image (URI constructed from Packer vars) so session warmup skips the ECR-pull leg, with graceful no-op failure when the image does not yet exist; an inline `nvidia-smi` + `nvcc` sanity check aborts the build if the GPU stack is broken. All inputs (region, AMI prefix, model URLs, model SHA256s, ECR account/tag) are var-driven; no URLs, accounts, or checksums are hardcoded. Output AMI and snapshot tagged `Project=panakoes`, `Environment=<env>`, `ManagedBy=packer`, `AmiPurpose=gpu-transcribe`, and `BakedAt=<UTC ISO timestamp>`. Boot volume encrypted (`encrypt_boot = true`) with the default `aws/ebs` key for dev. Per-build cost is roughly $0.20 to $0.50 (~10 to 20 minutes of g4dn.xlarge on-demand). README at `infra/ami/gpu-transcribe/README.md` documents `packer init / fmt / validate / build`, the required-vs-defaulted variable matrix, the rotation procedure (re-run build, point gpu-spawner Lambda at the new AMI ID), and the architectural rationale for baking models versus user-data installs (caps streaming session warmup at 45-80s instead of 3+ minutes). `infra/README.md` gains a new `## AMIs` section pointing at the module. Resolves backlog task #19.
- Terraform configuration `infra/dev/step-functions/` creating the STANDARD-type AWS Step Functions state machine `panakoes-dev-long-audio` that orchestrates the long-audio transcription pipeline (audio files exceeding the 10-minute Lambda-friendly threshold). The state machine runs `DetectDuration` -> `Choice` -> either `SubmitBatchSingle` (short path) or `ChunkAudio` -> parallel `Map` of `panakoes-dev-transcribe-batch` AWS Batch jobs (MaxConcurrency 8, 8-minute chunks with 30-second overlap) -> `MergeTranscripts` -> `WriteFinalTranscript`. Every Task carries a 3-attempt exponential-backoff retry policy (2/4/8 second intervals) and a `Catch States.ALL` handler that routes to a `NotifyFailure` Lambda which flips the ingestion record to `failed` and emits a `panakoes.transcribe / TranscriptionFailed` EventBridge event. Definition is built from a HCL local map and rendered with `jsonencode` for diff-able plan output. STANDARD workflow type chosen over EXPRESS because Express caps at 5-minute total execution and would break any chunked run that exceeds that wall-clock; STANDARD bills per state transition (well under a penny per execution) and persists the full execution audit trail. KMS-encrypted CloudWatch log group at `/aws/states/panakoes-dev-long-audio` (30-day retention, level `ALL` with `include_execution_data = true` for offline replay of failed runs). KMS resolution prefers the shared `infra/dev/observability/` CMK via `terraform_remote_state` with `try()` fallback to a fresh module-local CMK so the module remains self-applicable while observability is still in the backlog. Same `try()` pattern resolves the `infra/dev/batch/` job queue and definition; both fall back to constructed-by-name ARNs that match the documented naming convention. State-machine IAM role grants `lambda:InvokeFunction` on the five forward-referenced Lambda ARNs only (no wildcard on function name), `batch:SubmitJob` / `TerminateJob` on the transcribe job queue + definition only, `batch:DescribeJobs` on `*` (no resource-level authorization for this verb), `events:PutEvents` on the project bus only, the `events:Put*` verbs on the `StepFunctionsGetEventsForBatchJobsRule` managed rule used by the Map `.sync` integration, and the documented CloudWatch Logs delivery surface required for STANDARD workflow logging. X-Ray tracing enabled.
