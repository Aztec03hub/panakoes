### Changed
- `infra/dev/frontend`: switched CloudFront access logging from legacy v1 (S3 + log-delivery-write ACL) to v2 (CloudWatch Logs Delivery -> S3). The v1 path failed distribution creation against AWS's modern `BucketOwnerEnforced` default ObjectOwnership with `InvalidArgument: ... does not enable ACL access`. v2 keeps the bucket on the secure default (ACLs disabled), uses the `delivery.logs.amazonaws.com` service principal authorized via bucket policy, and partitions logs by `cloudfront/{yyyy}/{MM}/{dd}/{HH}/` for efficient Athena query later. Removes `aws_s3_bucket_ownership_controls.frontend_logs`, `aws_s3_bucket_acl.frontend_logs`, and the distribution's inline `logging_config` block; adds two bucket-policy statements (`AllowCWLDeliveryPutObject`, `AllowCWLDeliveryGetBucketAcl`) scoped via `aws:SourceAccount` and `aws:SourceArn` conditions, plus three new resources (`aws_cloudwatch_log_delivery_source.frontend_access`, `aws_cloudwatch_log_delivery_destination.frontend_access_s3`, `aws_cloudwatch_log_delivery.frontend_access`). Documented in module comments. Phil to re-run `scripts/tf.sh apply frontend` after merge.

The `panakoes-dev-daily-monthly` plan runs two rules: a daily 05:00 UTC backup with 30-day retention (5h start window, 7h completion window) and a monthly 05:00 UTC backup on the 1st with 365-day retention. `aws_backup_selection` protects the three DynamoDB tables in `infra/dev/data/` (ingestion, audit-log, streaming-sessions), listed both by ARN (immediate protection) and by `Backup = enabled` tag (steady-state mechanism; tag added to the data tables in a follow-up). IAM service role `panakoes-dev-backup` carries the AWS-managed `AWSBackupServiceRolePolicyForBackup` and `AWSBackupServiceRolePolicyForRestores` policies. `aws_backup_vault_notifications` publishes BACKUP_JOB_FAILED, BACKUP_JOB_EXPIRED, RESTORE_JOB_FAILED, COPY_JOB_FAILED, and RECOVERY_POINT_MODIFIED to a forward-constructed SNS topic ARN (`panakoes-dev-system-alerts`) that will be owned by a future `infra/dev/events/` module. No cross-region or cross-account copy in dev (production should add both).
- Terraform configuration `infra/dev/frontend/` creating the static-asset hosting tier for the SvelteKit admin app: a private S3 origin bucket `panakoes-dev-frontend-<suffix>` (CMK-encrypted with the new `alias/panakoes-dev-frontend`, versioning enabled, public access blocked, OAC-only GetObject via bucket policy with TLS-only deny defense-in-depth), an `aws_cloudfront_origin_access_control` (sigv4, s3 origin type) replacing the legacy OAI pattern, an `aws_cloudfront_distribution` named `panakoes-dev-admin` with default cache behavior (GET/HEAD only, redirect-to-https, compression on, AWS managed Caching-Optimized cache policy id `658327ea-...`, AWS managed Managed-SecurityHeadersPolicy response-headers policy id `67f7725c-...`), SPA-friendly custom error responses (403 + 404 -> `/index.html` 200) for SvelteKit client-side routing, CloudFront default certificate (custom domain + ACM cert deferred until DNS is wired), no geo restriction, `PriceClass_100` for cost discipline, and a separate `panakoes-dev-frontend-logs-<suffix>` access-log bucket (SSE-S3 because CloudFront standard logs require it; 90-day lifecycle expiry; `log-delivery-write` ACL via BucketOwnerPreferred). KMS key policy grants `cloudfront.amazonaws.com` Decrypt + GenerateDataKey scoped to this account so the OAC fetch path can decrypt CMK-encrypted objects. WAF association is pre-wired via `data "terraform_remote_state" "waf"` and a `var.associate_waf` toggle (default `false`) but deferred: the existing `infra/dev/waf/` ACL is `scope = REGIONAL` and CloudFront requires `scope = CLOUDFRONT`, so a future `infra/dev/waf-cloudfront/` module will provide the compatible ACL. Module README documents the deploy command (`pnpm build && aws s3 sync ... && aws cloudfront create-invalidation ...`).

Serializes plans per branch so two simultaneous PR pushes do not race for the DynamoDB state lock; the lock-timeout grants two minutes for an orphaned lock from a previous run to release before failing. cancel-in-progress is intentionally false because canceling mid-plan can leave the lock orphaned for up to 15 minutes.
